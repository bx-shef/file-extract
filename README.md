# file-extract — сервис разбора файлов

> Last reviewed: 2026-10-24

Внутренний сервис: получает файл и возвращает его текст, а для таблиц — ещё и каждый лист
отдельным CSV. Им пользуются другие сервисы линейки (toolsai-mcp, позже импорт прайсов и
клиент-банк), чтобы разбор жил в одном месте, а не копиями в каждом продукте.

Разбор перенесён из `ai-price-import` без смены смысла.

## Что умеет

| Формат | Как разбирается |
|---|---|
| TXT, CSV, TSV | чтение с определением кодировки: UTF-8, а если байты не UTF-8 — windows-1251 |
| PDF | `pdftotext -layout`; если текста почти нет (меньше 32 непробельных знаков) — это скан, идёт в OCR |
| DOC, DOCX, ODT, RTF | LibreOffice → простой текст |
| XLS, XLSX, ODS | LibreOffice → каждый лист в свой CSV (разделитель — табуляция, UTF-8), до 64 листов |
| PNG, JPG, JPEG, TIF, TIFF, BMP, WEBP | Tesseract, языки rus+bel+kaz+eng |
| PDF-скан | pdftoppm → PNG по страницам → Tesseract, до 30 страниц |

После разбора текст чистится в одной точке: убираются управляющие символы (нулевой байт и
прочие), переводы строк и табуляция остаются. Если читаемого не осталось — ошибка `unreadable`.

## API

### `POST /extract`

- Тело — сырые байты файла.
- `X-File-Name` — имя файла, **обязателен**: по расширению выбирается способ разбора.
  Нелатинские имена передавайте через `encodeURIComponent`.
- `Authorization: Bearer <EXTRACT_API_KEY>`.

```bash
curl -s -X POST http://file-extract:3000/extract \
  -H "Authorization: Bearer $EXTRACT_API_KEY" \
  -H "X-File-Name: $(node -p 'encodeURIComponent(process.argv[1])' 'Прайс.xlsx')" \
  --data-binary @Прайс.xlsx
```

Ответ `200`:

```json
{
  "text": "…",
  "sheets": [{ "name": "Лист1", "csv": "Товар\tЦена\n…", "rows": 12 }],
  "ocr": false,
  "truncated": false,
  "pages": 3,
  "cached": false,
  "kind": "office",
  "sha256": "…"
}
```

- `sheets` — только для таблиц, иначе пустой массив.
- `pages` — только для OCR (число распознанных страниц).
- `kind` — `text` / `pdf` / `office` / `image`.
- `truncated: true` — текст (или листы) длиннее `MAX_TEXT_CHARS` и обрезан.
- `cached: true` — ответ из кеша.

Ошибки — JSON `{ "error": "<код>", "message": "<текст>" }`:

| Статус | Код | Когда |
|---|---|---|
| 400 | `bad_request` | нет `X-File-Name` или пустое тело |
| 401 | `unauthorized` | нет ключа или ключ неверный |
| 413 | `too_large` | файл больше `MAX_FILE_BYTES` |
| 415 | `unsupported` | формат не поддерживается |
| 422 | `unreadable` | после разбора нет читаемого текста |
| 422 | `too_complex` | больше 64 листов, больше 30 страниц скана, слишком большой вывод программы |
| 422 | `extract_failed` | программа разбора упала на этом файле (обычно битый файл) |
| 503 | `busy` | очередь не дождалась места за `QUEUE_TIMEOUT_MS` — повторите позже |
| 504 | `timeout` | разбор не уложился в `EXTRACT_TIMEOUT_MS` |
| 500 | `internal` | неожиданная ошибка сервиса |

### `GET /health`

`200 {"ok": true, "version": "<версия разборщика>"}`, без ключа.

## Настройки (env)

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `EXTRACT_API_KEY` | — | общий ключ вызова, **обязателен**, не короче 16 знаков. Без него сервис не стартует (кроме `NODE_ENV=test`) |
| `PORT` | `3000` | порт внутри контейнера |
| `MAX_FILE_BYTES` | `20971520` (20 МБ) | потолок размера файла |
| `MAX_TEXT_CHARS` | `2000000` | потолок текста в ответе (и отдельно — листов) |
| `MAX_CONCURRENCY` | `2` | сколько файлов разбирается одновременно |
| `QUEUE_TIMEOUT_MS` | `60000` | сколько файл может ждать места |
| `EXTRACT_TIMEOUT_MS` | `120000` | потолок времени на файл; по нему дочерние процессы убиваются |
| `REDIS_URL` | — | задан — кеш в Redis |
| `CACHE_DIR` | `/tmp/file-extract-cache` | кеш на диске, если Redis не задан |

Неверное число в переменной — ошибка запуска, а не молчаливое умолчание.

## Кеш

- Ключ — sha256 от версии разборщика, способа разбора и sha256 файла. Сменилась логика
  разбора — поднимается `EXTRACTOR_VERSION` (`src/config.ts`), и старый кеш больше не отдаётся.
- Срок — **ровно 24 часа и не дольше**: в тексте персональные данные. Чтение срок не продлевает.
- Кешируется только успех.
- Redis держит срок сам (`SET … EX 86400`). На диске срок записан в mtime файла; просроченное
  удаляется при чтении и раз в час.
- Недоступный кеш — не отказ: файл просто разбирается заново.

## Изоляция и лимиты

Это чужие файлы, а LibreOffice и парсеры PDF исторически уязвимы. Поэтому:

- порт наружу не публикуется, сеть compose — `internal: true` (без выхода наружу);
- файловая система только для чтения, запись — только в tmpfs `/tmp`;
- лимит памяти (`mem_limit`) и числа процессов (`pids_limit`) на контейнер — главная граница
  против zip/XML-бомб: таймаут ограничивает время, но не память;
- не больше `MAX_CONCURRENCY` разборов одновременно, таймаут на файл и на каждый процесс (90 с);
  по таймауту убивается вся группа процессов (LibreOffice порождает дочерний `soffice.bin`);
- программы разбора получают окружение без секретов (белый список: `PATH`, локаль, шрифты…);
- LibreOffice — в `--safe-mode` (без макросов) и со своим профилем на каждый файл;
- каждый файл — в своём временном каталоге (`mkdtemp`), каталог удаляется в `finally`;
- образ работает не от root (пользователь `node`).

## Персональные данные

- В журнал пишется **только**: способ разбора (`kind`), размер, время, первые 12 знаков sha256,
  признак кеша и код ошибки. **Никогда** — имя файла и текст. Поля журнала закрыты типом.
- Текст ошибки, который уходит вызывающему, не содержит имени файла и содержимого.
- Файл хранится только на время разбора; результат — в кеше не дольше 24 часов.

## Запуск

```bash
pnpm install
pnpm typecheck
pnpm test
EXTRACT_API_KEY=$(openssl rand -hex 32) pnpm start   # нужны pdftotext, libreoffice, tesseract в PATH
```

В Docker:

```bash
docker build -t file-extract .
docker run --rm --read-only --tmpfs /tmp -e EXTRACT_API_KEY=$(openssl rand -hex 32) file-extract
```

Пример для compose — `docker-compose.example.yml`. Образ публикуется в
`ghcr.io/bx-shef/file-extract` на каждый push в `main`.
