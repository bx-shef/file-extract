# file-extract — сервис разбора файлов

> Last reviewed: 2026-10-24

Внутренний сервис: получает файл и возвращает его текст, а для таблиц — ещё и каждый лист
отдельным CSV. Им пользуются другие сервисы линейки (toolsai-mcp, позже импорт прайсов и
клиент-банк), чтобы разбор жил в одном месте, а не копиями в каждом продукте.

Разбор перенесён из `ai-price-import` без смены смысла.

## Что умеет

| Формат | Как разбирается |
|---|---|
| TXT, CSV, TSV | чтение с определением кодировки: UTF-8, а если байты не UTF-8 — windows-1251 |
| PDF | `pdftotext -layout`, первые 500 страниц; если текста почти нет (меньше 32 непробельных знаков) — это скан, идёт в OCR |
| DOC, DOCX, ODT, RTF | LibreOffice → простой текст |
| XLS, XLSX, ODS | LibreOffice → каждый лист в свой CSV (разделитель — табуляция, UTF-8), до 64 листов |
| PNG, JPG, JPEG, TIF, TIFF, BMP, WEBP | Tesseract, языки rus+bel+kaz+eng; картинка больше 50 Мпикс (по заголовку PNG/JPEG/TIFF/BMP) — отказ до OCR |
| PDF-скан | pdftoppm → PNG по страницам → Tesseract, до 30 страниц |

После разбора текст чистится в одной точке: убираются управляющие символы (нулевой байт и
прочие), переводы строк и табуляция остаются. Если читаемого не осталось — ошибка `unreadable`.

## API

### `POST /v1/extract`

Порядок проверок: ключ → имя файла и формат → объявленный размер → место для приёма тела →
тело → кеш → место в очереди разбора → разбор.

- Тело — сырые байты файла.
- `X-File-Name` — имя файла, **обязателен**: по расширению выбирается способ разбора.
  Нелатинские имена передавайте через `encodeURIComponent`.
- `Authorization: Bearer <EXTRACT_API_KEY>`.

```bash
curl -s -X POST http://file-extract:3000/v1/extract \
  -H "Authorization: Bearer $EXTRACT_API_KEY" \
  -H "X-File-Name: $(node -p 'encodeURIComponent(process.argv[1])' 'Прайс.xlsx')" \
  --data-binary @Прайс.xlsx
```

Ответ `200`:

```json
{
  "text": "…",
  "sheets": [{ "name": "Лист1", "csv": "Товар\tЦена\n…", "rows": 12 }],
  "ocr": false,
  "truncated": false,
  "pages": 3,
  "cached": false,
  "kind": "office",
  "sha256": "…",
  "extractorVersion": "0.2.0-1"
}
```

- `sheets` — только для таблиц, иначе пустой массив.
- `pages` — только для OCR (число распознанных страниц).
- `kind` — `text` / `pdf` / `office` / `image`.
- `truncated: true` — текст (или листы) длиннее `MAX_TEXT_CHARS` и обрезан.
- `cached: true` — ответ из кеша.
- `extractorVersion` — версия разборщика, давшего результат (входит в ключ кеша).

Ошибки — JSON `{ "error": "<код>", "message": "<текст>" }`:

| Статус | Код | Когда |
|---|---|---|
| 400 | `bad_request` | нет `X-File-Name` или пустое тело |
| 401 | `unauthorized` | нет ключа или ключ неверный |
| 404 | `not_found` | нет такого адреса (в том числе старый `/extract`) |
| 405 | `method_not_allowed` | не тот метод (`/v1/extract` — только POST, `/health` — только GET) |
| 413 | `too_large` | файл больше `MAX_FILE_BYTES` (по `Content-Length` или по телу) |
| 415 | `unsupported` | формат не поддерживается |
| 422 | `unreadable` | после разбора нет читаемого текста |
| 422 | `too_complex` | больше 64 листов, лист CSV больше 50 МБ, больше 30 страниц скана, картинка больше 50 Мпикс, слишком большой вывод программы |
| 422 | `extract_failed` | программа разбора упала на этом файле (обычно битый файл) |
| 503 | `busy` | очередь полна (`MAX_QUEUE`) или не дождалась места за `QUEUE_TIMEOUT_MS` — повторите позже |
| 504 | `timeout` | разбор не уложился в `EXTRACT_TIMEOUT_MS` |
| 500 | `internal` | неожиданная ошибка сервиса |

**Временные и постоянные отказы** (для повторов у вызывающего, toolsai-mcp#83): `503` и `504`
— временные, повторять можно (с паузой); `400`, `401`, `413`, `415`, `422` — постоянные, повтор
того же файла даст тот же ответ. `500` — сбой сервиса, повторять осторожно.

На `401`, `413` и `503` сервис закрывает соединение после ответа, не дочитывая тело.
Клиент, закрывший соединение раньше ответа, прерывает свой разбор (и ожидание в очереди); в
журнале это `client_aborted`, ответа нет.

### `GET /health`

`200 {"ok": true, "version": "<версия разборщика>"}`, без ключа.

## Настройки (env)

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `EXTRACT_API_KEY` | — | общий ключ вызова, **обязателен**, не короче 16 знаков. Без него сервис не стартует (кроме `NODE_ENV=test`) |
| `HOST` | `127.0.0.1` | адрес, на котором слушает сервис. В образе Dockerfile задаёт `0.0.0.0` |
| `PORT` | `3000` | порт внутри контейнера |
| `MAX_FILE_BYTES` | `20971520` (20 МБ) | потолок размера файла |
| `MAX_TEXT_CHARS` | `2000000` | потолок текста в ответе (и отдельно — листов) |
| `MAX_CONCURRENCY` | `2` | сколько файлов разбирается одновременно |
| `MAX_QUEUE` | `8` | сколько запросов может ждать места; сверх — сразу `503`. Разборы + очередь — столько тел (до `MAX_FILE_BYTES`) одновременно в памяти |
| `QUEUE_TIMEOUT_MS` | `60000` | сколько файл может ждать места |
| `EXTRACT_TIMEOUT_MS` | `300000` | потолок времени на файл (5 минут — OCR 30 страниц); по нему дочерние процессы убиваются |
| `REDIS_URL` | — | задан — кеш в Redis |
| `CACHE_DIR` | `/tmp/file-extract-cache` | кеш на диске, если Redis не задан |
| `CACHE_MAX_BYTES` | `268435456` (256 МБ) | потолок дискового кеша; сверх — вытесняются записи, истекающие раньше |

Неверное число в переменной — ошибка запуска, а не молчаливое умолчание.

## Кеш

- Ключ — sha256 от версии разборщика, способа разбора, расширения файла (одни байты под `.xls`
  и `.doc` LibreOffice разбирает разными фильтрами), `MAX_TEXT_CHARS` (обрезка — до кеша) и
  sha256 файла. Сменилась логика
  разбора — поднимается `EXTRACTOR_VERSION` (`src/config.ts`), и старый кеш больше не отдаётся.
- Срок — **ровно 24 часа и не дольше**: в тексте персональные данные. Чтение срок не продлевает.
- Кешируется только успех.
- Redis держит срок сам (`SET … EX 86400`). На диске срок записан в mtime файла; просроченное
  удаляется при чтении и раз в час.
- Недоступный кеш и испорченная запись — не отказ: файл просто разбирается заново.
- Дисковый кеш ограничен `CACHE_MAX_BYTES` (tmpfs — это память контейнера).
- ⚠ Не подключайте общий Redis MCP-сервера: у него AOF на диск, `noeviction` и 64 МБ — кеш с
  персональными данными записался бы на диск и выдавил бы токены. Только свой Redis без тома.

## Изоляция и лимиты

Это чужие файлы, а LibreOffice и парсеры PDF исторически уязвимы.

⚠ **Сетевая изоляция и лимиты действуют только при запуске по примеру compose
(`docker-compose.example.yml`) или по `docker run` ниже** — сам код их не обеспечивает. Лимита
памяти на отдельный процесс разбора нет: граница — лимит памяти контейнера.

```bash
docker run --rm --network none --memory 1536m --cpus 1 --pids-limit 256 \
  --cap-drop ALL --security-opt no-new-privileges \
  --read-only --tmpfs /tmp:size=1g,noexec,nosuid,nodev \
  -e EXTRACT_API_KEY=… ghcr.io/bx-shef/file-extract:<sha коммита>
```

(`--network none` — для разовой проверки; в стеке — внутренняя сеть `internal: true`.)

Что делает сам сервис:

- слушает `127.0.0.1`, пока `HOST` не задан (в образе — `0.0.0.0` для внутренней сети);
- не больше `MAX_CONCURRENCY` разборов и `MAX_QUEUE` ожидающих; столько же тел одновременно в
  памяти; число соединений ограничено (`maxConnections`);
- таймаут на файл и на каждый процесс (90 с); по таймауту и при уходе клиента убивается вся
  группа процессов (LibreOffice порождает `soffice.bin`), она же добивается после завершения;
- программы разбора получают окружение без секретов (белый список: `PATH`, локаль, шрифты…), а
  `HOME`, `XDG_*`, `TMPDIR` и рабочий каталог — свой временный каталог разбора;
- LibreOffice — со свежим профилем на каждый файл, в профиле: уровень безопасности макросов 3 и
  запрет макросов, запрет загрузки ссылок из документа (`BlockUntrustedRefererLinks`), запрет
  обновления внешних связей в Calc и Writer. `--safe-mode` не используется: он подменяет профиль
  временным и отбрасывает эти настройки (проверено вживую — с ним внешняя картинка снова
  запрашивается). Сеть этим закрыта не до конца — граница сети всё равно контейнер;
- бомбы: картинка больше 50 Мпикс — отказ до OCR по заголовку файла; лист CSV больше 50 МБ —
  отказ до чтения; `pdftotext` читает не больше 500 страниц; вывод программы — до 64 МБ;
- путь CSV из вывода LibreOffice принимается, только если он внутри своего рабочего каталога;
- каждый файл — в своём временном каталоге (`mkdtemp`), каталог удаляется в `finally`;
- образ работает не от root (`USER 1000:1000`), базовый образ закреплён по digest.

## Персональные данные

- В журнал пишется **только**: способ разбора (`kind`), размер, время (`ms`) и ожидание в
  очереди (`queueMs`), первые 12 знаков sha256, признак кеша, код ошибки и для `500` — класс
  системной ошибки (`errorClass`, например `ENOSPC`, без текста). **Никогда** — имя файла и
  текст. Поля журнала закрыты типом, набор ключей держит тест.
- Служебные события журнала: `start` (с `version`), `cache_sweep` (с `removed`),
  `cache_sweep_failed`.
- Текст ошибки, который уходит вызывающему, не содержит имени файла и содержимого.
- Файл хранится только на время разбора; результат — в кеше не дольше 24 часов.

## Запуск

```bash
pnpm install
pnpm typecheck
pnpm test
EXTRACT_API_KEY=$(openssl rand -hex 32) pnpm start   # нужны pdftotext, libreoffice, tesseract в PATH
```

В Docker:

```bash
docker build -t file-extract .
docker run --rm --read-only --tmpfs /tmp -e EXTRACT_API_KEY=$(openssl rand -hex 32) file-extract
```

Интеграционный тест (`tests/integration.test.ts`) гоняется на настоящих программах, если
`soffice` и `pdftotext` есть в `PATH`; в CI их нет — он пропускается.

Пример для compose — `docker-compose.example.yml`. Образ публикуется в
`ghcr.io/bx-shef/file-extract` на каждый push в `main` с тегом sha коммита (и `latest`); в
compose указывайте тег sha.
