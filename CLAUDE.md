# CLAUDE.md — file-extract

> Last reviewed: 2026-11-08

Внутренний сервис разбора файлов: файл → текст и листы таблиц. Голый `node:http`, Node 22,
TypeScript запускается через `node --experimental-strip-types` (сборки нет), тесты — vitest.
Задача — bx-shef/file-extract#1. Разбор перенесён из `bx-shef/ai-price-import`
(`server/utils/textExtract.ts`, `extractRunners.ts`, `textSanitize.ts`) без смены смысла.

## Команды

```bash
pnpm install
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest run
pnpm start       # node --experimental-strip-types src/main.ts (нужен EXTRACT_API_KEY)
docker build -t file-extract .
```

## Конвенции

- **Имя файла и текст в журнал — никогда.** Поля журнала закрыты типом `LogEntry`; новое поле —
  только несекретное. Текст ошибки наружу — без имени файла.
- **Сменил логику разбора — подними `EXTRACTOR_VERSION`**, иначе сутки отдаётся старый кеш.
- **Срок кеша — ровно 86400 с, не дольше**; чтение срок не продлевает; кешируется только успех.
- **Fail-closed:** без `EXTRACT_API_KEY` сервис не стартует (кроме `NODE_ENV=test`).
- **Только стираемый синтаксис TypeScript** (`erasableSyntaxOnly`): без `enum`, `namespace` и
  параметр-свойств конструктора — `--experimental-strip-types` их не исполнит. Импорты — с `.ts`.
- **Процессы разбора — только через `run()`**: окружение без секретов, свой рабочий каталог
  (cwd/HOME/XDG), таймаут, убийство группы (и после обычного завершения).
- **LibreOffice — без `--safe-mode`**: он отбрасывает профиль с `LO_REGISTRY` (проверено вживую).
- **Новый вход, от которого зависит ответ, — в ключ кеша** (`CacheKeyInput`).
- **Тест краснеет при мутации кода**; откат мутации — из копии, не `git checkout --`.
- Код и имена — по-английски; комментарии, документация, коммиты — по-русски.
- Штамп `> Last reviewed: YYYY-MM-DD` под заголовком каждого `.md`.

## Ревью PR

Объём ревью задаёт **уровень** PR по путям изменённых файлов: `tools/review-tier.sh --action`
(`--explain` — по файлам). Правила репозитория — `tools/review-tier.rules`; сам движок — копия
эталона bx-shef/toolsai, здесь его не правят. Уровень PR — наибольший из уровней его файлов; не
подошло ни одно правило — уровень 1. Порядок действий — навык `review-panel`
([SKILL.md](.claude/skills/review-panel/SKILL.md)). Основная проверка — `pnpm check`; она же сверяет правила уровней.

| уровень | что меняется | ревью | примеры |
|---|---|---|---|
| 0 | только документы, версии, тесты без кода сервиса, `.gitattributes` | без ревью: основная проверка | правка главы справки, строка в CHANGELOG, подъём версии, новый тест |
| 1 | мелкое поведение: всё, что не 0 и не 2 | `/code-review medium --max-findings 5`; уровень `max` запрещён | исправление в одном классе, текст интерфейса, новая настройка без денег и прав |
| 2 | деньги, лицензия, безопасность, установщик, сборка, CI, Dockerfile и образы, публичный API, схема таблиц | панель из пяти параллельно; `/code-review` при панели не зовём | расчёт квоты или цены, проверка лицензии, токен и права, установщик, `Dockerfile`, публичный API, новая таблица |

- **Ручной уровень** главнее автоматического: `tools/review-tier.sh --level N` или `REVIEW_TIER=N`; его же
  задаёт слово владельца («уровень 2», «панель», «без ревью») или строка «Уровень ревью: N» в описании PR.
  Вывод показывает оба: «вручную N, по путям M». Легенда уровней — `tools/review-tier.sh --levels`.
- Агент вправе **поднять** уровень сам (сомнение; правка выросла из рассуждения, а не из замера; в тексте
  цена или условия лицензии), **понизить** вправе только владелец: ручной уровень ниже автоматического
  печатает предупреждение. Пути с пометкой «слово владельца» — стоп до слова владельца.
- Панель: все пять ролей (Документация, Инженер, QA, Безопасность, CTO) — Sonnet, среднее усилие;
  максимум усилия — никогда. Панель проверяет образ, Dockerfile, ключи, порты, выкладку.
- Повтор: после правок перепроверяет только нашедший замечание; полная панель заново — только если
  PR переписан; серия связанных PR — одна панель на общий дифф.
- Находки чинятся в том же PR; отклонённая находка — с доводом и замером, а не молча. Отчёт —
  по-русски, коротко.

### Режим агентов: «экономия» и штатный

**Режим «экономия» (сейчас):** по умолчанию Sonnet, среднее усилие; Opus, высокое — только деньги,
лицензии, безопасность, установщик, сложные падения; максимум усилия — никогда; агентов 6–8 за раз
(больше — спросить владельца); на стенде одна сборка за раз.

**Штатный режим:** Opus, высокое — деньги, лицензии, безопасность, установщик, сложный дизайн;
Sonnet — механика (ветки, тексты, снимки, чек-листы); низкое усилие — неприоритетное.

## Версии и выпуск

У сервиса есть версия (решение владельца 2026-10-28), semver: `version` в `package.json` = верхний
заголовок `## X.Y.Z — ГГГГ-ММ-ДД` в `CHANGELOG.md`; выпуск — тег `vX.Y.Z` и релиз GitHub. Выпущено:
**0.2.1** (тег `v0.2.1`). `GET /health` отдаёт `version` = `EXTRACTOR_VERSION` (`0.2.0-1`) —
версия разборщика: версия продукта + номер правки логики разбора (ключ кеша).

- Каждый PR — пункт в `CHANGELOG.md` под «Не выпущено» (сверху).
- Выпустить: отдельный PR — «Не выпущено» → `## X.Y.Z — дата`, та же версия в `package.json`
  (и приставка `EXTRACTOR_VERSION`, если менялась логика разбора); после мержа —
  `gh release create vX.Y.Z --target <sha> --title X.Y.Z --notes-file <раздел CHANGELOG>`.
- Образ — `ghcr.io/bx-shef/file-extract:<полный sha коммита>` и `latest` (CI на push в `main`): toolsai-mcp закрепляет его в `FILE_EXTRACT_TAG`. Вручную образы не пушить.
- Сторонние actions в CI — запинены на SHA.

## Разовые контейнеры проверок

- Любые разовые `docker run` для проверок (Playwright, node, php…) — только через `../stand/tools/pw-run.sh <проект> <задача> [опции docker run] -- <команда>` (bx-shef/toolsai-stand, клон рядом). Образ Playwright — по умолчанию, другой — `PW_IMAGE=node:22`. Прямой `docker run` для проверок не использовать: обёртка задаёт лимиты памяти и CPU, shm 1 ГБ, --init, отключает дампы WSL, даёт имя, метку project и таймаут (PW_TIMEOUT). Не больше двух прогонов одновременно. Пример: `PW_TIMEOUT=900 ../stand/tools/pw-run.sh <репо> check -v D:/tmp/chk:/w -w /w -- bash -c './build.sh --check'`.
