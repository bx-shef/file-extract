## 0.4.0 — 2026-11-17

- **Замеры нагрузки** (bx-shef/file-extract#34): скан PDF 30 страниц — 97 с и 0,33 ГБ на одном ядре, xlsx 18,8 МБ — 5 с и 0,48 ГБ, docx — 0,9 с; LibreOffice стартует при файловой системе только для чтения; портал во время разбора не тормозит. Выбор `MAX_CONCURRENCY`, `cpus`, `mem_limit`, таймаутов — `docs/dev/MEASUREMENTS.md`: прежние значения (1 разбор, 1 ядро, 1536m, 300 с) подтверждены. Код не менялся.
- **Одинаковые одновременные запросы делят один разбор** (bx-shef/file-extract#35): запрос с тем же ключом кеша, пока файл разбирается, ждёт итог первого (а не запускает OCR второй раз) и получает тот же ответ, отказ — тоже общий. Клиент, начавший разбор, ушёл — разбор идёт для оставшихся; ушли все — прерывается. Ждущие входят в потолок тел `MAX_CONCURRENCY + MAX_QUEUE`; ключ — тот же, что у кеша, разные файлы и настройки не склеиваются. В журнале поле `shared`. `src/server.ts` (`startFlight`/`awaitFlight`), API.md.
- **Метрики и готовность** (bx-shef/file-extract#38): `GET /metrics` (тот же ключ, что у разбора; текст Prometheus) — запросы по маршруту и статусу (в т. ч. 503, 504, 499), попадания и промахи кеша, присоединения к чужому разбору (`shared_total`, `flights`), глубина очереди, занятые места, тела в памяти, память и её пик. `GET /health` остаётся живостью (200, `version`, без ключа) и получает `ready` и `checks` (программы разбора в PATH, кеш пригоден); `/health?ready=1` — 503 при неготовности. Недоступный кеш разбор не останавливает. `src/metrics.ts`, README, API.md.
- **Ключи потребителей** (bx-shef/file-extract#36): `EXTRACT_API_KEYS` — `метка:ключ` (MCP, импорт прайсов, клиент-банк); метка — в журнале (`consumer`), ключ — нигде; утечка одного ключа остальных не открывает; ротация — две записи с одной меткой. Метка входит в ключ кеша (формат `k4`, кеш сбрасывается один раз): один потребитель не узнаёт по `cached`, что файл присылал другой. Старый `EXTRACT_API_KEY` работает (метка `default`). Одинаковый ключ у двух меток и короткие ключи — ошибка запуска без печати ключей. `src/auth.ts` (`authenticate`), `src/config.ts` (`parseConsumers`), README «Ключи потребителей».
- **Сканирование образа и цепочка поставок** (bx-shef/file-extract#37): `tools/scan-image.sh` — Trivy (образ закреплён по digest, через tar без сокета Docker) и SBOM CycloneDX; запуск руками (через `pw-run.sh`) и в CI (`ci.yml`: PR и публикация; `scan.yml`: раз в неделю по `latest`). Публикация образа с `provenance: mode=max` и `sbom: true` (аттестации BuildKit). Пока без падения CI (`SCAN_EXIT: '0'`): первый прогон нашёл 12 исправимых HIGH в базовом образе (apt, пакеты npm в node:22-slim) — решение о включении падения за владельцем. `.trivyignore` — исключения с причиной и сроком. README «Сканирование образа и цепочка поставок».
- Документация: сервис зрения — bx-shef/toolsai-vision (вынесен из toolsai-light 16.11): README «Зрение», `.env.example`, `docker-compose.example.yml`, CLAUDE.md. Код и настройки (`VISION_URL`, `VISION_API_KEY`) не меняются.

## 0.3.0 — 2026-11-15

- **Картинка → текст и описание** (bx-shef/toolsai-light#13, bx-shef/toolsai-assistant#676): с `VISION_URL` и `VISION_API_KEY` картинка с получением места разбора, параллельно с OCR, уходит в сервис зрения toolsai-light (`data:`-адресом); в ответе `text` начинается с «Описание картинки: …», поле `description` — само описание. Зрение начинается с получением места разбора и идёт своим местом (одна картинка в работе, две ждут не дольше половины `VISION_TIMEOUT_MS`, лишние — без описания): место разбора и место тела в памяти не держит. В зрение — только PNG, JPEG, WEBP по байтам файла и не больше 50 Мпикс; ответ — не больше 64 КБ, описание без управляющих символов и знаков направления. Сбой зрения — картинка с текстом OCR, `vision_failed` в журнале (формат, размер и уход клиента — не сбой), и такой ответ не кешируется; фото без текста со зрением — не `unreadable`, а при временном сбое зрения (занято, таймаут, сеть, 5xx, 429) — 503 `busy` (повторить), не «нет текста». `VISION_URL` проверяется разбором адреса (без логина, запроса и якоря). Размеры WEBP — и для проверки 50 Мпикс перед OCR. Ключ кеша (формат `k3`) учитывает зрение у картинок; `EXTRACTOR_VERSION` — `0.2.0-2` (правка логики уже в ключе кеша; выпуск 0.3.0 его не меняет — повторный сброс кеша ничего не дал бы). Пример compose — своя внутренняя сеть `vision` между file-extract и зрением. `src/vision.ts`, настройки `VISION_*`, README «Зрение», API.md.
- Ревью уровня 2 — двое проверяющих; панель из пяти — только при деньгах и лицензиях (решение владельца 14.11.2026): `tools/review-tier.sh` (копия эталона), навык `review-panel` и раздел «Ревью PR» в `CLAUDE.md` называют состав уровня 2 — «Безопасность» и «Инженер/QA» (оба Sonnet, среднее усилие, мутаций не больше 3 на PR), панель из пяти — только при деньгах и лицензиях (Безопасность и CTO — Opus, высокое усилие); перепроверку делает тот же агент. Режим «экономия»: один фоновый исполнитель помимо основной сессии, мутаций не больше 3 и один прогон проверки на PR. (лента: нет)
- Лицензия: права на программу у ООО «БэИксШефБай» вместо MIT; `LICENSE`, `package.json`, README приведены в соответствие.
- **Сборка документа: HTML → PDF/DOCX** (bx-shef/toolsai-assistant#385, PR #20): `POST /v1/convert?to=pdf|docx`, тело — HTML (UTF-8 без BOM) до 5 МБ, ответ — байты файла (`application/pdf` / Word). LibreOffice Writer (`--infilter=HTML (StarWriter)`) со своим профилем и настройками безопасности разбора; тот же ключ, очередь, потолок одновременных тел и таймаут, без кеша. HTML сперва разбирается линейным сканером (кавычки, комментарии, `<style>`) и пересобирается (`src/htmlGuard.ts`): LibreOffice получает только проверенное, в одной записи; ссылки в документе — текстом (`<a>` и `href` отбрасываются). Белый список: картинки — только `data:image/png|jpeg|gif;base64,…`, формат по сигнатуре (не по метке MIME: svg под меткой png LibreOffice читает как вектор и встраивает локальные файлы), размеры по заголовку, все картинки документа вместе — не больше `MAX_IMAGE_PIXELS` (50 Мпикс, как в разборе OCR); `url()` — только такие же картинки, записанные как есть; без iframe/object/link/base/script/svg/form, `@import` и `<meta>` кроме `charset="utf-8"`; иначе 400 `unsafe_html` с причиной. Проверка линейная (200 000 знаков «<» — миллисекунды). Нужен shef.cowork с `disk_doc_build`. Образ пересобрать; новых пакетов нет (`libreoffice-writer` уже в образе).

## 0.2.0 — 2026-10-24

Доработки по ревью панели (bx-shef/file-extract#2). Версия разборщика `0.2.0-1` — старый кеш
не отдаётся.

- Адрес разбора — `POST /v1/extract` (старый `/extract` убран, клиентов не было); ответ несёт
  `extractorVersion`.
- Безопасность: `x.constructor`/`x.__proto__` больше не считаются форматом; путь CSV из вывода
  LibreOffice — только внутри своего каталога и по последней стрелке; LibreOffice со свежим
  профилем (макросы выключены, ссылки и внешние картинки не грузятся, связи не обновляются)
  вместо `--safe-mode`, который этот профиль отбрасывал; `HOME`/`XDG_*`/`TMPDIR`/cwd процессов —
  рабочий каталог разбора.
- Бомбы: картинка больше 50 Мпикс — отказ до OCR; лист CSV больше 50 МБ — отказ до чтения;
  `pdftotext -l 500`.
- Нагрузка: `MAX_QUEUE` (8) — переполнение очереди сразу `503`; тела в памяти не больше
  «разборы + очередь»; `maxConnections`. Уход клиента прерывает разбор и ожидание
  (`client_aborted`, не `500`). После `401`/`413`/`503` соединение закрывается.
- Процессы: группа добивается и после обычного завершения (не остаётся `soffice.bin`).
- Кеш: ключ учитывает расширение и `MAX_TEXT_CHARS`; дисковый кеш ограничен
  `CACHE_MAX_BYTES` (256 МБ); сбой создания каталога больше не закрывает кеш до перезапуска.
- Обрезка текста не режет суррогатную пару.
- Умолчания: `HOST=127.0.0.1` (в образе `0.0.0.0`), `EXTRACT_TIMEOUT_MS=300000`.
- Журнал: `queueMs`, `errorClass` для `500`, событие `cache_sweep_failed`.
- Образ: `node:22-slim` по digest, `USER 1000:1000`. Compose — под ВМ портала (1 ядро, 1,5 ГБ,
  один разбор), отдельный tmpfs под кеш, `noexec,nosuid,nodev`, образ по тегу sha.
- CI: `packages: write` только у джобы публикации на `main`, `persist-credentials: false`;
  Dependabot для npm, actions и docker.
- Тесты: журнал (ровно разрешённые ключи), 413 и закрытие соединения, срок кеша, временные
  каталоги, `503 busy`, уход клиента, интеграционный тест на настоящих программах.

## 0.1.0 — 2026-10-24

Первая версия (bx-shef/file-extract#1).

- Разбор перенесён из ai-price-import без смены смысла: TXT/CSV/TSV (UTF-8 или windows-1251),
  PDF через pdftotext с откатом на OCR для сканов, Office через LibreOffice (каждый лист в свой
  CSV, до 64 листов), картинки и сканы PDF через Tesseract rus+bel+kaz+eng (до 30 страниц),
  очистка текста в одной точке.
- `POST /extract` (тело — файл, имя — `X-File-Name`) и `GET /health`.
- Листы таблиц в ответе (`sheets: [{name, csv, rows}]`), признаки `ocr`, `truncated`, `pages`.
- Общий ключ вызова `EXTRACT_API_KEY`, сравнение за постоянное время; без ключа сервис не стартует.
- Кеш на 24 часа (Redis или диск), ключ с версией разборщика.
- Ограничение одновременных разборов с очередью, таймаут на файл с убийством группы процессов.
- Журнал без имён файлов и текста.
- Docker-образ с проверкой программ при сборке, пример compose с изоляцией, CI с публикацией в GHCR.
