# Ревью PR: уровень по путям, `/code-review` и панель из пяти

> Last reviewed: 2026-11-08

Правила — [CLAUDE.md](../../../CLAUDE.md), раздел «Ревью PR». Этот навык — порядок действий. Расходятся —
прав CLAUDE.md, а навык правится в том же PR.

## 1. Подготовка

1. `git fetch origin main && git merge origin/main` в ветку PR — проверяем то,
   во что PR вольётся. Чужую ветку не перебазируем.
2. Написать **простыми словами**, что PR делает и зачем, в 3–6 строк. Не
   пишется коротко — PR делает слишком много, сказать об этом.
3. `pnpm check` (`pnpm typecheck && pnpm test`) — зелёный. Ровно это гоняет CI (джоба `ci`); туда же
   входит сверка правил уровней — тест `tests/reviewTier.test.ts` (`tools/review-tier.sh --self-test`).
   Разовый контейнер для проверки — только через обёртку `pw-run.sh` из bx-shef/toolsai-stand
   (CLAUDE.md, «Разовые контейнеры проверок»), не прямым `docker run`.

## 2. Уровень ревью

`tools/review-tier.sh --action` — уровень по путям изменённых файлов, `--explain` — по файлам и
сработавшим правилам, `--levels` — легенда уровней. Правила — `tools/review-tier.rules`.
Уровень PR — наибольший из уровней его файлов.

| уровень | что меняется | что делаем | примеры |
|---|---|---|---|
| 0 | только документы, версии, тесты без кода сервиса, `.gitattributes` | ревью нет: основная проверка (`pnpm check`) | правка главы справки, строка в CHANGELOG, подъём версии, новый тест |
| 1 | мелкое поведение: всё, что не 0 и не 2 | `/code-review medium --max-findings 5`. Уровень пишем явно: скилл запоминает прошлый. `max` и `ultra` запрещены | исправление в одном классе, текст интерфейса, новая настройка без денег и прав |
| 2 | деньги, лицензия, безопасность, установщик, сборка, CI, Dockerfile и образы, публичный API, схема таблиц | панель из пяти параллельно (п. 3); `/code-review` при панели не зовём | расчёт квоты или цены, проверка лицензии, токен и права, установщик, `Dockerfile`, публичный API, новая таблица |

- **Ручной уровень** главнее автоматического. Его задаёт слово владельца («уровень 2», «панель», «без ревью»)
  или строка «Уровень ревью: N» в описании PR: тогда `tools/review-tier.sh --level N --action`
  (или `REVIEW_TIER=N`). Вывод показывает оба: «вручную N, по путям M».
- Агент вправе **поднять** уровень сам: сомнение; правка выросла из рассуждения, а не из замера;
  в тексте цена или условия лицензии. **Понизить** вправе только владелец: ручной уровень ниже
  автоматического печатает предупреждение.
- Пути с пометкой «слово владельца» (правило `hold` в `tools/review-tier.rules`) меняются только по
  слову владельца.
- Какая модель и усилие у агентов, сколько агентов за раз — режим «экономия» или штатный,
  CLAUDE.md, «Ревью PR».

## 3. Панель — пять агентов одним сообщением, параллельно

| роль | модель, усилие | смотрит |
|---|---|---|
| **Документация** | Sonnet, среднее | `README.md`, `docs/dev/API.md`, `docs/dev/README.md`, `.env.example`, `docker-compose.example.yml`, `CLAUDE.md` (карта кода, конвенции), `CHANGELOG.md` (пункт под «Не выпущено»): верно ли против кода, сверена ли документация с правкой, открываются ли ссылки, сходятся ли имена, пределы и коды ошибок |
| **Инженер** | Sonnet, среднее | `Dockerfile` (`node:22-slim@sha256`, `tini`, poppler, LibreOffice, tesseract); процессы разбора — только через `run()`: окружение без секретов, свой рабочий каталог, таймаут, убийство группы; ключ кеша (`CacheKeyInput`) и `EXTRACTOR_VERSION` при смене логики разбора; контракт `POST /v1/extract` и `GET /health`; только стираемый синтаксис TypeScript; типы |
| **QA** | Sonnet, среднее | краснеет ли тест, если сломать код (мутация — только в отдельном `git worktree`); всё ли заявленное в PR проверено; `tests/integration.test.ts` пропускается без `soffice` — что можно проверить только на живом образе, так ли и названо |
| **Безопасность** | Sonnet, среднее | `EXTRACT_API_KEY` — fail-closed, ключ только в `.env`; имя файла и текст — никогда в журнал (`LogEntry`); порт не публикуется, сеть `internal: true`, `read_only`, `cap_drop: ALL`, лимит `pids`; запуск внешних программ без командной инъекции; персональные данные из файлов — рабочий каталог разбора удаляется, кеш не дольше 24 часов и не на постоянном диске; цепочка поставки — digest образа, `pnpm-lock.yaml`, actions по SHA |
| **CTO** | Sonnet, среднее | изменение целиком: объём, нагрузка и лимиты, выкладка (образ `ghcr.io/bx-shef/file-extract` тегами `latest` и полным sha, откат), контракт с потребителями (toolsai-mcp, чтение файлов в shef.cowork); не решение ли это владельца |

Модель — параметр запуска агента. Усилие — как позволяет среда запуска; **максимум усилия — никогда**.

Каждому в задании — дословно по смыслу:

- Начни с `git diff origin/main...HEAD --stat`, читай по делу, не грузи всё дерево, не упади по
  таймауту.
- Дерево общее. Чужая правка — сосед, не откатывать и не строить на ней теорий.
- Код меняет только QA и только чтобы проверить, что тест краснеет, — в
  отдельном `git worktree`. Откат мутации — из копии во временном каталоге,
  **никогда** `git checkout --`.
- Поведение сверять с кодом в `src/`, контракт — с `docs/dev/API.md`, поведение poppler, LibreOffice и
  tesseract — с их документацией или запуском, не по памяти.
- Ключи, вебхуки и данные клиентов в отчёте не цитировать — в том числе имена и содержимое
  разбираемых файлов.
- Сообщать находки: файл:строка, что, почему важно, как чинить, насколько
  уверен. Не чинить.

## 4. Отчёт владельцу — по-русски, коротко

Блок на проверяющего: **кто — что — почему важно — как чинить**. Без
стенограмм. Отдельно — что берёшь в работу и что нет, с причиной и замером.

## 5. Исправления и повтор

- Всё — **в этом же PR**. Просится в отдельный issue или PR — не выносить
  молча, сказать и обсудить.
- Исправленный гард — с тестом, который краснеет при мутации (CLAUDE.md, «Конвенции»).
- После правок: `pnpm check`, пуш. Перепроверяет **только нашедший**
  замечание: та же роль, один агент, смотрит исправление.
- Вся панель заново — только если PR переписан. Серия связанных PR — **одна панель
  на общий дифф** серии, а не по панели на каждый PR.
